# FrameCut · 视频裁剪

导入 AVI / MP4，在画面上自由选框，设置开始与结束时间，然后导出 MP4 或 AVI。支持一次选择多个视频，每个视频保留自己的裁剪设置。

视频只在使用者的浏览器中处理，应用不上传视频。源文件始终保持不变。

## 使用

1. 点击“导入视频”，或把文件拖入网页；也可点击左侧“导入文件夹”，一次加入文件夹与子文件夹里的 AVI / MP4。其他格式会自动忽略。
2. 拖动选框边角调整大小，拖动内部移动；在选框外拖动可以重新选区。右侧也能直接输入像素坐标与宽高。
3. 设置开始和结束秒数，或者用滑块定位后点击“当前帧设为起点 / 终点”。
4. 选择 MP4（通用、重新压缩）或 AVI（FFV1 无损编码），点击“导出视频”。完成后可以再次点击“保存视频”。

点击“上一个视频 / 下一个视频”或左侧素材列表逐个查看。文件夹导入按相对路径自然排序（例如 2 在 10 前）；不同子文件夹中的同名视频分别保留，重复导入同一文件夹不会重复加入。每个视频分别记住当前页面内的裁剪位置、时间、比例和导出设置；刷新网页后不保留。导入仅建立列表，选中时才读取预览，不会同时解码整个文件夹。

未压缩、无音频的 RGB AVI（24 位 BI_RGB）直接从本地文件读取当前帧播放，不再生成整段 MP4 预览；你提供的 5 个大 AVI 均使用此路径。仅保留当前帧与一个待显示帧，切换视频时释放旧帧。磁盘较慢时预览会跳帧以跟上播放时间；导出始终从原文件读取，保留原始帧率。浏览器支持的 MP4 继续原生播放；其他 AVI / MP4 仍采用 PNG 定位和转码播放预览。

## 限制

- 建议在电脑上的 Chrome / Edge 使用。首次加载约 31 MB 处理引擎。
- 单个输入文件须小于 2 GiB，这是当前 WebAssembly 引擎的限制。WORKERFS 按需读取原文件，避免将整个输入文件复制到处理内存。
- 输出暂存在浏览器内存中。可导出的大小取决于电脑与浏览器可用内存；较大的无损输出可缩小选区或缩短时间。不能保证任意尺寸与时长的视频都能在浏览器处理。
- 选框按原视频像素定位，对齐至偶数像素；时间边界以实际视频帧为准。界面帧步进按平均帧率估算，变帧率视频不保证每次恰好跨过一帧。
- AVI 是容器，不同编码的兼容性取决于随附 FFmpeg 解码器。输出 FFV1 AVI 建议使用 VLC 播放。
- 刷新或关闭网页会清除本次选择与未保存结果。处理期间请保持网页打开。

## 本地运行 / 自行部署

需要 Node.js 18 或更新版本：

```sh
npm ci
npm run build
npm run preview
```

打开终端显示的 `http://127.0.0.1:4173`。`dist/` 为可部署的纯静态网站，支持子目录部署，不需要服务器转码或 API 密钥。请通过 HTTP(S) 打开，不能直接双击 HTML。

处理引擎从锁定的 npm 包生成，构建时拆成两个小于 25 MiB 的静态文件；浏览器加载后重新合并。应用处理功能不依赖运行时第三方 CDN。

## 验证

测试材料仅在本地，未提交视频、帧图或导出样本。

已用实际样本验证：

- MP4：1944 × 1944，4 秒；AVI：2432 × 2032，3 fps，42.333 秒，1,882,840,064 字节。
- 两种输入均导出为 320 × 240、1–3 秒的 MP4；AVI 另导出为 FFV1 AVI。
- 独立原生 FFmpeg 解码检查输出尺寸、时长；无损输出首帧与原视频在对应时间、坐标的 RGB 像素逐字节相等。
- 真实大 AVI 完整 42.333 秒、800 × 600 导出；选框拖动、比例、AVI 播放预览、取消后重试、切换素材、错误文件恢复、保留音频 / 静音与手机宽度布局。
- 导入和处理过程中未发生视频网络上传。

预览修复：overlay AVI 在旧版 JPEG 预览编码时可复现 `Buffer reallocation failed` / `memory access out of bounds`；单独解码成功，改为 PNG 预览后通过。已补测 5 个真实 AVI 的预览与切换、overlay 在 1/20/41 秒定位、播放、MP4/FFV1 裁剪导出，并以原生 FFmpeg 验证无损输出对应首帧像素完全一致。

本地重现：`node test-browser.mjs <包含 MP4 和 avi 子目录的路径>`。
直接播放检查：`node test-fast-preview.mjs`；包含 5 个真实 AVI、定位、暂停、时间终点、播放中切换 / 导出、MP4 回归及未调用 FFmpeg 预览转码断言。预览帧的浏览器 RGBA SHA-256 写入本地报告，可与原生 FFmpeg 解码独立比较。

overlay 回归检查：在本项目目录运行 `node test-overlay.mjs`，测试数据位于上一级的 `avi` 目录，且包含 `*_overlay.avi`。
独立验证脚本 `verify-exports.py` 需要把 `imageio-ffmpeg` 安装到 `test-results/native-tools`。
`test-interactions.mjs` 另需要 `test-results/audio-source.mp4`（带声音的 4 秒测试视频）。

页面为支持 WebMCP 的浏览器注册读取编辑状态、设置裁剪参数两个工具。当前测试浏览器没有原生 WebMCP，工具注册的真实宿主验证未执行，不影响普通网页功能。
